# 软件 roofline 一页结论（round-49，`software_roofline_r49.json` / `scripts/software_roofline.py`）

**口径声明**：本页全部数字为**模型 FLOPs 与强制搬运量推导**，**不是 HBM 实测**。无 PCM 计数器，`hardware_status=unverified` 维持；真实 HBM 读写字节、HBM 带宽利用率、矩阵单元 activity 均 **BLOCKED**。
输入 SHA256 见 JSON 的 `input_sha256`；字段版本 `roofline_v1`；时间单位 ms。

## 四组核心结果

| 组 | 调用/步 | 设备 ms/步 | 有效 TFLOP/s | vs 139.2 峰值 | 同卡实测参考 | 算术强度 |

## 三种情况的判别

| 情况 | 证据 | 判定 |
|---|---|---|
| **① 计算效率低 → kernel 调优空间** | 反向 GEMM 88–129 TF/s = 峰值 63%–93% | **存在但有界**：距参考 7%–37%；转置视图 dW 形状最弱（88 TF/s，63%）。理论上限 ≤ 772 × 37% ≈ **285 ms/步**，实际远小；属**厂商侧** kernel 调优 |
| **② 强制流量高 / 算术强度低 → 减少转置与中间缓冲** | dW 算术强度 **656–706 FLOP/B**（远高于 roofline 转折点 ~50）| **强计算受限，非带宽受限**。`.contiguous()` 复制是真实的额外流量项（S=512 dW 升维 **+8,053 MB/步**、降维 +2,013 MB/步），单列不并入 GEMM 本体——这解释了原生+连续化**更慢**（中位 +32.4 ms）而 FlagGems 仍微 gain（其 Triton kernel 在连续操作数上的收益略高于复制成本）|
| **③ 阶段设备时间不高但关键路径空闲大 → 减少提交间隙/融合** | 每步空闲 **211–250 ms（8%–12%）** | **存在但无法归因**：空闲来自提交间隙还是暴露的复制，需 host 泳道（**BLOCKED**）|

**带宽下限的重要警示**：按 shape 聚合的 `bw_lb_gbps`（1.2e5–2.3e5 GB/s）假设每次调用都重新搬运全部操作数字节、无片上复用，**超出任何 HBM 带宽，是公式下限的伪影，不能读作达到或所需的 HBM 带宽**。真实 HBM 流量必须靠 PCM 计数器。

## 与当前候选对齐（`route_isolated_r48.json`）

- **py_route**（Triton `mm_kernel_general` 528 次 + 原生 2,688 次）vs **native**（原生 3,216 次）：整步配对差 **−18.8/−3.3/−7.9/−3.2/+0.1/−11.1，中位 −5.6 ms，5/6 更快**——唯一方向为正的候选，幅度在波动内
- **native_contig**（原生 + 显式 `.contiguous()`）：**6/6 更慢，中位 +32.4 ms**——额外复制流量（+8,053 MB/步）未被收益覆盖，方案关闭
- 三种路径强制字节下限（S=512 dW 升维）：native 5,838 MB / FlagGems 含内部复制 13,892 MB / 显式复制 13,892 MB

## 结论边界

**可提交**：有效 TFLOP/s、相对理论/同卡参考比例、强制字节与算术强度、阶段占比、关键路径空隙。
**BLOCKED（需 PCM）**：真实 HBM 读写字节、HBM 带宽利用率、矩阵单元 activity、空闲的主机泳道归因。
**所需协助**（`hbm_blocked_r46.md`）：平台释放 PCM 窗口 / 等价计数器工具；厂商确认指标层级。

## 下一步方向（按证据排序）

1. **厂商侧**：原生 mm 对**转置视图操作数**的专用路径（当前 88 TF/s vs 连续 129 TF/s，差 32%）——最直接、最大绝对收益
2. **训练态 SDPA 候选**（attention 合计 28.6%）：FlagGems 已排除，需支持真实 mask/dropout/反向的实现
3. **短形状融合/批处理**：9–12 TF/s 的 140–180 行形状
4. **空闲归因**：需 host 泳道后再决定是否优化提交间隙
