# 软件 roofline 一页结论（round-55 修正版，复审 BqpXfeg）

**口径**：模型 FLOPs 与**逻辑字节率**推导，**非 HBM 实测**。`hardware_status=unverified`；HBM 字节/带宽利用率/矩阵单元 activity **BLOCKED**。

## 本轮四项修正

1. **分词预取**：修复共享 FIFO 样本错配（按组名取 future + 回归用例）；逐项核对实际送入模型的 `input_ids`/`attention_mask`；重测 12 步配对。
2. **gap attribution v3**：host 事件**先裁剪到 gap 边界再取并集**（旧版把跨边界事件的整个时长计入）。回归样例 s4 2.600 ms gap：覆盖 **0.109** / UNKNOWN **2.491**（预期 ~0.110/~2.49 ✓）。
3. **headroom 按实际 token 维分组**：dW 取归约维 K，dX 取输出行维 M（旧版 `max(M,K)` 把 FFN 固定特征维 4096 计为长序列）。
4. **窗口分列**：单步 718.73 ms 与三步均值 772.12 ms 不再相除，"93.1% 覆盖率"与"53.39 ms 未测"已清除。

## 分词预取：修复后 —— **稳定整步收益**（第 1、2 项）

**上轮（round-54）结论作废**：共享 FIFO 让先完成的负样本被当作 positive；loss 异常**不是** tokenizer 非线程安全，而是我的代码 bug。

**修复**：按组名取 future（`concurrent.futures` dict）；回归用例 `test_prefetch_order.py` **复现旧 bug（slot positive 取到 negative_1）并验证修复**。

**正确性 PASS**：4 micro × 5 组 = **60 个张量/运行**的实际 `input_ids`+`attention_mask` 哈希**逐项字节一致**；loss 最大偏差 **0.0096**（原生波动带内）；**零 loss 异常**（两模式）。

**性能：12/12 步全部更快**（4 次重复，A→B / B→A 交错，profiler 关，原入口同步边界保留，token 统计移出计时区）：

| 重复（组序）| overlap − inline (ms) |
|---|---|
| rep1（A→B）| −33.0 / −20.5 / −33.1 |
| rep2（B→A）| −19.2 / −8.7 / −20.2 |
| rep3（A→B）| −27.7 / −24.1 / −34.7 |
| rep4（B→A）| −33.1 / −25.4 / −25.0 |
| **12 步** | 中位 **−25.2 ms**（−34.7…−8.7）≈ **1.2% 整步** |

有效 tokens/s：13,810/14,415/14,677 → 14,046/14,552/14,880。每步实际隐藏 tokenize ~8.6–13.6 ms（审阅者指出的 34–39 ms 是三步合计）。

**对训练方案的影响**：**候选可采纳**——保持训练语义与精度、无需改 kernel、整步稳定收益、与运行顺序无关。`hardware_status=unverified` 维持，待 records 托管与 PCM 完成后方可 deployable。
