# 软件 roofline 一页结论（round-51 修正版，复审 bqj7-Bw）

**口径**：模型 FLOPs 与**逻辑字节率**推导，**非 HBM 实测**。`hardware_status=unverified`；HBM 字节/带宽利用率/矩阵单元 activity **BLOCKED**。字段版本 `roofline_v1`，单位 ms。

## 本轮四项修正

1. **带宽单位修正**：`bytes/(ms×10⁶)` = 十进制 GB/s。S=512 FFN 升维 dW 回归用例：5,838.47 MB / 46.80 ms = **124.75 GB/s**（旧值 124,754 GB/s，**放大 1000 倍**）。该指标更名为"按每个操作数读写一次估算的**逻辑字节率**"，缓存复用与重复读取会改变实际 HBM 流量。**"强计算受限"降级为待验证假设**。
2. **12 个 dW 形状对齐**：按操作数维度 + **A 转置标志** + 阶段关联，与路由白名单**精确匹配 12/12**（6 dW_ffn_up + 6 dW_ffn_down，旧版误含 3 行 dX）。两条基线中位数**分别从各自 6 个配对差生成**：**Python dW 路由 −5.6 ms，显式连续化 +32.35 ms**（旧 JSON 把后者填到了前者，源文件已修正并加 `FIELD_FIX_NOTE`）。
3. **逐形状优化空间 + 覆盖率**：**撤回"整步最多省 285 ms"**（系 6 行外推）。
4. **空隙归因**：按单微批次 CPU 标记切窗（纳入跨边界设备事件、裁剪后取并集），`gap_attribution_r51.json`。

## dW 路由三条路径逐形状计时（第 2 项，12/12 有记录）

| 路径 | 每步合计 ms | 相对 native |
|---|---:|---:|
| native（转置视图）| 183.06 | — |
| FlagGems（含内部连续化）| 150.60 | **−32.46** |
| 显式 `.contiguous()` + native | 214.19 | **+31.16** |

仅 M/K/N、dtype（bf16）、布局（转置 A）全匹配的记录标为同形状参照。单算子层面 FlagGems 省 32 ms，但整步 Python 路由只兑现 **−5.6 ms**（中位）——差额即 host 分发开销；显式连续化单算子就**更慢**（+31 ms），整步 +32.35 ms 一致。

## 空隙归因（第 4 项，`gap_attribution_r51.json`）

按单微批次切窗：每前向窗口空闲 **28–38 ms**，最大单段 **3–5 ms**；≥2 ms 空隙合计 30–60 ms/步。

**所有最大空隙的起止都精确对齐**：从前一个 kernel **结束**开始，到 `Memcpy HtoD (Pageable→Device)` **开始**结束；空隙起点无 cpu_op 运行 → **host 侧 tokenize**（`prepare_embedding_inputs`，每微批次 5 组）阻塞设备。微基准确认 **H2D 本身只 0.029 ms**，不是 3–5 ms 的来源。

## 训练决策：假设 → 实验 → 判定

**假设**：把组 i+1 的 tokenize 与组 i 的设备计算重叠可消除大部分每微批次空隙。
**单因素对照**（只改 tokenize 时机；同快照/输入/分词器/H2D/数学；`F.normalize` 尾部与真实 `embedding_batch` 一致；profiler 关；两次重复组序轮换；3 真实步）：

| 重复（组序）| overlap − inline (ms) |
|---|---|
| rep1（inline → overlap）| −3.7 / −1.0 / +1.7 |
| rep2（overlap → inline）| +2.9 / −9.0 / +7.7 |
| **6 步** | 中位 **+0.35 ms，3/6 为负** |

loss 等价性：两模式首 micro loss 相对差 **0.4%**（bf16 级）。
**判定：假设被否定**——6 次配对差方向变号，整步持平。host 已被 tokenize 占满，重叠引入同步点而非隐藏它。
**首次运行勘误**：第一次漏掉 `F.normalize`（loss ~1568 而非 ~2.9），该批数据已丢弃；修正后重跑才是本结果。
