**在保持训练语义与精度的前提下，尚无可部署的整步改动——保留原生路径。** 分词预取在原始入口上**更慢**（12/12，中位 +27.7 ms，已关闭）；H2D 非阻塞化无显著差异（−1.8 ms，CI [−10.1, +8.1]）；dW Python 路由在含动量的同快照对照下逐 micro 逐位相同，整步**有小幅收益迹象，尚不足以部署**（进程级 −9.03 ms，Welch 95% CI [−20.67, +2.60]）。

## 精度

- **同状态单步对照（两次真实 AdamW 更新后的快照，含动量）**：dW 路由、overlap 预取、H2D 非阻塞、autocast 内的 r56 实现，在 4 个 micro 的累积稠密梯度（386 张量）、更新后参数（388）、稠密优化器状态（1158）、裁剪前梯度范数、loss、键集合上与原生**逐位相同**；仅 word / position 两张 embedding 表的梯度及其优化器状态不同（原生自比亦然）。r56 的实现（autocast 外）**FAIL**。
- **为什么轨迹级对比不可用**：第一次 backward 的梯度跨进程就有 0.26% 的元素不同；第一次更新后约 0.0007% 的参数相差 1 ulp；而把 **1 个**权重移动 1 个 bf16 ulp 就能让 micro-batch loss 变化 0.0018（温度 0.05 放大）。给定相同 state 时前向逐位可复现，所以同状态对照有效，从 step 0 起的轨迹对比无效。
- **FlagGems dW 确实执行**：从预热 step 1 起每进程 96 次、命中步 432 次 `flag_gems.mm`；step 0 的路由偏差与原生自比同范围；命中步 grad norm 的组间差异同样出现在从不调用 FlagGems 的「仅回退」组，不能归到 FlagGems 上。
