# 发布与后续建设

当前版本提供目录、模板和安装管理入口。尚无经过本仓库硬件复验的 profile/bundle，也没有自动构建离线 bundle 的发布工具。

后续发布流程：固定本地修复所在管理仓库 commit 和所有 submodule 指针 → 校验 patch/目标 hash → 对指定环境执行单项及组合验收 → 锁定 bundle 的条目版本和应用顺序 → 发布带 checksums、来源与许可证的制品。

工具版本、schema 版本、bundle 版本分别维护。GitHub 自动生成的源码压缩包不包含 submodule 内容，不能直接宣传为可离线使用的完整包。完整离线包需要专门构建并测试。

平台负责人提供精确设备/软件栈、命令、日期、输入规模、判定标准和结果；发布负责人核对证据和制品对应关系。普通 CI 通过不代表设备通过。旧 release 的固定 submodule 不随后续更新变化。

上游包含修复后，记录合入 commit、首个包含修复的版本和适用范围；仍需要修复的旧基线可保留历史条目。
